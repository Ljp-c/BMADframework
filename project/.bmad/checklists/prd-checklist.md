# PRD Quality Checklist (PRD质量检查清单)

## 使用说明

本检查清单用于评审产品需求文档(PRD)的质量，确保文档完整、清晰、可执行。

---

## 1. 文档基础

- [ ] 文档信息完整(版本、作者、日期、状态)
- [ ] 有清晰的修订历史记录
- [ ] 文档结构清晰、有目录
- [ ] 使用统一的术语和格式

## 2. 产品概述

- [ ] 产品愿景清晰明确
- [ ] 产品定位描述完整
- [ ] 核心价值主张清晰
- [ ] 目标用户定义完整

### 用户画像检查
- [ ] 主要用户类型已识别
- [ ] 用户特征描述完整
- [ ] 用户需求和痛点已说明
- [ ] 用户场景已描述

## 3. 功能需求

### 功能列表
- [ ] 功能列表完整
- [ ] 每个功能有唯一标识
- [ ] 功能优先级已定义(MoSCoW)
- [ ] 功能状态已标注

### 功能详细规格
- [ ] 每个功能有详细描述
- [ ] 用户流程已定义
- [ ] 业务规则已说明
- [ ] 界面原型或描述已提供

### 验收标准
- [ ] 每个功能有明确的验收标准
- [ ] 验收标准可测试
- [ ] 验收标准无歧义
- [ ] 边界条件已考虑

## 4. 非功能需求

### 性能需求
- [ ] 页面加载时间要求已定义
- [ ] API响应时间要求已定义
- [ ] 并发用户数要求已定义
- [ ] 数据处理量要求已定义

### 安全需求
- [ ] 认证授权要求已定义
- [ ] 数据安全要求已定义
- [ ] 接口安全要求已定义
- [ ] 安全合规要求已说明

### 可用性需求
- [ ] 系统可用性目标已定义
- [ ] 数据备份策略已定义
- [ ] 故障恢复要求已定义

### 兼容性需求
- [ ] 浏览器支持范围已定义
- [ ] 设备支持范围已定义
- [ ] 操作系统支持范围已定义
- [ ] 屏幕分辨率要求已定义

## 5. 数据需求

- [ ] 主要数据实体已识别
- [ ] 数据字段定义完整
- [ ] 数据关系已说明
- [ ] 数据验证规则已定义
- [ ] 数据保留策略已说明

## 6. 接口需求

### 外部接口
- [ ] 外部接口列表完整
- [ ] 接口用途已说明
- [ ] 接口提供方已确认

### 内部接口
- [ ] 内部接口需求已说明
- [ ] 接口依赖关系已识别

## 7. 约束条件

### 技术约束
- [ ] 技术约束已识别
- [ ] 约束原因已说明
- [ ] 约束影响已评估

### 业务约束
- [ ] 业务约束已识别
- [ ] 约束原因已说明
- [ ] 约束影响已评估

### 时间约束
- [ ] 时间约束已识别
- [ ] 里程碑已定义
- [ ] 交付物已明确

### 资源约束
- [ ] 人力资源约束已识别
- [ ] 预算约束已识别
- [ ] 基础设施约束已识别

## 8. 风险与假设

### 风险评估
- [ ] 风险已识别
- [ ] 风险影响已评估
- [ ] 风险可能性已评估
- [ ] 缓解措施已制定

### 假设条件
- [ ] 假设条件已列出
- [ ] 假设合理性已评估
- [ ] 假设验证方法已说明

## 9. 可执行性

### 技术可行性
- [ ] 已与架构师确认技术可行性
- [ ] 技术风险已评估
- [ ] 技术依赖已识别

### 资源可行性
- [ ] 开发资源已评估
- [ ] 时间资源已评估
- [ ] 预算资源已评估

### 范围合理性
- [ ] MVP范围已定义
- [ ] 范围与资源匹配
- [ ] 范围与时间匹配

## 10. 审批确认

- [ ] 产品经理已审核
- [ ] 技术负责人已审核
- [ ] 利益相关者已确认
- [ ] 文档已正式发布

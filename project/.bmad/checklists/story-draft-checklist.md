# Story Draft Checklist (用户故事草稿检查清单)

## 使用说明

本检查清单用于评审用户故事草稿的质量，确保故事符合INVEST原则，具备进入细化的条件。

---

## 1. INVEST原则检查

### Independent (独立性)
- [ ] 故事与其他故事相互独立
- [ ] 故事可以单独开发
- [ ] 故事可以单独测试
- [ ] 故事可以单独交付

### Negotiable (可协商)
- [ ] 故事细节可以讨论
- [ ] 故事范围可以调整
- [ ] 实现方式可以协商

### Valuable (有价值)
- [ ] 故事对用户有明确价值
- [ ] 故事对业务有明确价值
- [ ] 价值可以量化或描述

### Estimable (可估算)
- [ ] 开发团队理解故事内容
- [ ] 技术实现方案大致明确
- [ ] 工作量可以估算

### Small (小的)
- [ ] 故事范围适中
- [ ] 故事可在1-3天内完成
- [ ] 故事不会超过13点

### Testable (可测试)
- [ ] 故事有明确的验收标准
- [ ] 验收标准可以验证
- [ ] 测试方法可以定义

## 2. 故事描述

### 故事格式
- [ ] 使用标准格式(作为...我想要...以便于...)
- [ ] 角色定义清晰
- [ ] 功能描述清晰
- [ ] 价值说明清晰

### 业务背景
- [ ] 业务背景已说明
- [ ] 业务价值已说明
- [ ] 用户场景已描述

## 3. 验收标准

### 标准完整性
- [ ] 验收标准已列出
- [ ] 验收标准覆盖主要场景
- [ ] 验收标准无歧义

### 标准质量
- [ ] 验收标准可测试
- [ ] 验收标准可验证
- [ ] 验收标准具体明确

## 4. 技术说明

### 前端说明
- [ ] 前端实现要点已说明
- [ ] UI组件需求已识别

### 后端说明
- [ ] 后端实现要点已说明
- [ ] API需求已识别

### 数据库说明
- [ ] 数据库变更需求已识别
- [ ] 数据模型影响已评估

## 5. 依赖关系

### 前置依赖
- [ ] 前置依赖已识别
- [ ] 依赖类型已说明
- [ ] 依赖影响已评估

### 后置依赖
- [ ] 后续故事已识别
- [ ] 阻塞关系已说明

## 6. 测试场景

### 测试覆盖
- [ ] 正向场景已列出
- [ ] 异常场景已列出
- [ ] 边界场景已列出

### 测试数据
- [ ] 测试数据需求已识别
- [ ] 测试数据准备方案已说明

## 7. 优先级与估算

### 优先级
- [ ] 故事优先级已定义
- [ ] 优先级理由已说明

### 故事点
- [ ] 故事点已估算
- [ ] 估算依据已说明

## 8. 文档完整性

- [ ] 故事ID已分配
- [ ] Epic归属已明确
- [ ] 状态已标注
- [ ] 作者已标注
- [ ] 日期已标注

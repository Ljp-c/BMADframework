# Story Ready Checklist (用户故事就绪检查清单) - 智能体对话记录

## 文档信息

> **PO**: 本文档记录了用户故事就绪评审的智能体对话交互过程。我们使用检查清单确保用户故事已准备好进入开发。

---

## 第一轮对话：就绪定义确认

### 话题：就绪标准

**PO**: 开始用户故事就绪检查。故事只有在满足所有就绪标准后才能进入开发。

**Dev**: 就绪标准是什么？

**PO**: 就绪标准（Definition of Ready）：
1. 故事符合INVEST原则
2. 验收标准清晰可测试
3. 技术方案已确认
4. 依赖已解决
5. 团队已承诺

---

## 第二轮对话：故事完整性检查

### 话题：故事内容完整性

**PO**: 检查故事完整性。

**QA**: 故事完整性检查：

**文档完整**:
- [ ] 故事文档完整
- [ ] 所有必填字段已填写
- [ ] 格式规范统一

**故事描述**:
- [ ] 用户故事格式正确
- [ ] 角色定义清晰
- [ ] 功能描述明确
- [ ] 价值说明清楚

**业务背景**:
- [ ] 业务背景完整
- [ ] 价值主张清晰

---

## 第三轮对话：INVEST原则确认

### 话题：INVEST原则验证

**PO**: 确认INVEST原则。

**QA**: INVEST原则确认：

| 原则 | 验证问题 | 状态 |
|------|----------|------|
| **I**ndependent | 这个故事可以独立开发吗? | [ ] |
| **N**egotiable | 细节可以和团队协商吗? | [ ] |
| **V**aluable | 这个故事对用户有价值吗? | [ ] |
| **E**stimable | 团队能估算工作量吗? | [ ] |
| **S**mall | 可以在一个迭代内完成吗? | [ ] |
| **T**estable | 验收标准可测试吗? | [ ] |

**Dev**: 确认故事独立可开发。

---

## 第四轮对话：验收标准确认

### 话题：验收标准可测试性

**PO**: 确认验收标准可测试性。

**QA**: 验收标准确认：

**功能验收**:
- [ ] 每个AC都可测试
- [ ] AC描述无歧义
- [ ] 边界条件已覆盖
- [ ] 预期结果明确

**非功能验收**:
- [ ] 性能要求可验证
- [ ] 安全要求可验证
- [ ] 可访问性要求可验证

**QA**: 验收标准清晰，可以编写测试用例。

---

## 第五轮对话：技术方案确认

### 话题：技术可行性

**PO**: 确认技术方案。

**Dev**: 技术方案确认：

**前端实现**:
- [ ] 技术方案已确定
- [ ] 组件已规划
- [ ] 接口已协调

**后端实现**:
- [ ] API已设计
- [ ] 数据模型已确定
- [ ] 第三方集成已评估

**技术风险**:
- [ ] 技术风险已识别
- [ ] 风险缓解措施已制定

**Architect**: 技术方案确认可行。

---

## 第六轮对话：依赖解决确认

### 话题：依赖状态

**PO**: 确认依赖状态。

**QA**: 依赖状态确认：

**前置依赖**:
- [ ] 前置依赖故事已完成
- [ ] 或依赖故事同时在开发
- [ ] 接口契约已协调

**后置依赖**:
- [ ] 影响范围已通知
- [ ] 接口变更已同步

**外部依赖**:
- [ ] 第三方服务可用
- [ ] 环境已准备

---

## 第七轮对话：团队承诺确认

### 话题：团队承诺

**PO**: 确认团队承诺。

**Dev**: 团队承诺确认：

**理解确认**:
- [ ] 开发团队理解故事内容
- [ ] 验收标准已确认
- [ ] 技术方案已确认

**承诺确认**:
- [ ] 故事点已确认
- [ ] 迭代容量已评估
- [ ] 团队已承诺完成

**QA**: 测试计划已准备。

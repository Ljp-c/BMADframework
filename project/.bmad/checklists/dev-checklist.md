# Developer Code Quality Checklist (开发者代码质量检查清单)

## 使用说明

本检查清单用于全栈开发者进行代码质量和实施完整性的自检，确保代码满足规范、功能完整、测试充分、文档齐全，可以交付给QA测试。

---

## 1. 代码实现质量

### 功能完整性
- [ ] 所有用户故事的验收标准已实现
- [ ] 功能边界与设计一致
- [ ] 异常流程和边界情况已处理
- [ ] 功能集成测试通过

### 代码规范
- [ ] 代码遵循编码规范(coding-standards.md)
- [ ] 命名规范统一(文件、函数、变量)
- [ ] 代码结构清晰，避免过深嵌套
- [ ] 函数/方法长度合理(≤100行)
- [ ] 复杂度控制(圈复杂度≤10)

### 代码可读性和注释
- [ ] 代码逻辑清晰易懂
- [ ] 复杂算法添加了算法注释
- [ ] 技术决策有说明
- [ ] 不明显的实现有行注释
- [ ] 没有过时或错误的注释
- [ ] 关键业务规则已注释

### 错误处理和异常管理
- [ ] 所有可能的异常都已捕获
- [ ] 异常处理逻辑合理(不吞掉异常)
- [ ] 错误信息清晰有用
- [ ] 特殊业务异常已定义
- [ ] 日志记录覆盖关键路径
- [ ] 日志等级使用正确(DEBUG/INFO/WARN/ERROR)

### 性能优化
- [ ] 避免了 N+1 查询问题
- [ ] 数据库查询已优化(适当索引、避免全表扫描)
- [ ] 缓存策略已实现(热数据、计算结果等)
- [ ] 代码中没有明显的性能瓶颈
- [ ] 大数据处理使用了分页/流式处理
- [ ] 循环中避免了重复轻量计算

## 2. 测试覆盖

### 单元测试
- [ ] 关键业务逻辑有单元测试
- [ ] 代码覆盖率≥80%
- [ ] 测试用例覆盖正常路径
- [ ] 测试用例覆盖边界条件
- [ ] 测试用例覆盖异常场景
- [ ] Mock/Stub 使用恰当
- [ ] 测试用例是独立的(可单独运行)
- [ ] 测试运行时间合理(<5ms/test)

### 集成测试
- [ ] 关键功能流程已集成测试
- [ ] 跨模块交互已测试
- [ ] 外部依赖(数据库、API等)已正确集成
- [ ] 测试数据完整、可重复
- [ ] 集成测试隔离(不相互影响)

### 边界条件和异常场景测试
- [ ] 输入验证测试(null/空/特殊字符等)
- [ ] 范围边界测试(最大值、最小值、0等)
- [ ] 超限情况测试(超时、资源耗尽等)
- [ ] 并发场景测试(竞态条件等)
- [ ] 错误恢复测试(数据库连接失败等)

### 测试用例文档完整
- [ ] 测试用例有清晰的描述
- [ ] 测试数据已准备
- [ ] 预期结果明确定义
- [ ] 测试执行步骤清晰可复现

## 3. 文档完整性

### 技术设计文档
- [ ] 技术实现方案已文档化
- [ ] 关键设计决策有记录
- [ ] 折中方案选择有说明
- [ ] 风险评估已记录

### API 文档更新
- [ ] 新增/修改的接口已文档化
- [ ] 接口入参和出参已定义
- [ ] 接口异常情况已说明
- [ ] 接口示例代码已提供
- [ ] API 版本信息已更新

### 代码变更说明
- [ ] 提交信息清晰规范(feat/fix/refactor等)
- [ ] 关键代码变更有说明
- [ ] 重构的目标和方法已说明
- [ ] 破坏性变更有迁移指南

### 部署说明文档
- [ ] 新增依赖已记录(package.json/requirements.txt等)
- [ ] 环境变量需求已说明
- [ ] 数据库迁移脚本已准备(如有)
- [ ] 部署步骤文档已更新
- [ ] 回滚方案已记录

## 4. 协作与交付

### 代码审查
- [ ] 代码已经过级联(≥1个同行审查)
- [ ] 审查意见已全部回复
- [ ] 反馈的问题已修复
- [ ] 审查人已批准合并

### 与 QA 的交接清单
- [ ] QA 已获得最新的测试环境
- [ ] 功能演示已进行
- [ ] 已知限制已说明
- [ ] QA 提问已全部回答
- [ ] 测试用例设计已讨论

### 构建和打包检查
- [ ] 代码构建成功(无编译错误)
- [ ] 所有自动化测试通过
- [ ] Lint/静态分析通过(无高级别问题)
- [ ] 打包产物验证通过
- [ ] 版本号已更新(如需要)

### 版本控制记录规范
- [ ] 分支名规范(feature/bugfix/hotfix等)
- [ ] 提交历史清晰(每个提交是独立的功能单位)
- [ ] 提交消息遵循约定(Conventional Commits)
- [ ] 无多余的合并提交或调试提交
- [ ] 标签已打好(Release标签等)

---

## 检查说明

- **绿色通过**：所有项都勾选(✓) 时，代码已准备好交付给QA
- **需要改进**：有未勾选项时，返工修复后重新检查
- **边界情况**：对于某些项可能需要与团队讨论确认(如覆盖率目标)

## 常见问题

**Q: 覆盖率80%是否适用所有项目？**
A: 这是推荐值，可根据项目特点调整。高风险模块应≥90%，简单模块可≥70%。

**Q: 是否所有代码都需要单元测试？**
A: 重点覆盖业务逻辑和复杂算法，UI交互代码可依赖集成测试。

**Q: 代码审查必须≥1人吗？**
A: 推荐至少1人，对于关键改动建议2人审查。

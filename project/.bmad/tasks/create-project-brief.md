# Task: Create Project Brief (创建项目简报)

## 任务描述

作为业务分析师，创建项目简报文档，清晰定义项目背景、目标、范围、约束条件和成功标准，为后续产品开发奠定基础。

## 角色执行者

**Analyst (业务分析师)**

## 输入

- 业务想法或需求描述
- 利益相关者访谈记录
- 现有系统分析(如有)
- 市场调研数据(如有)

## 输出

- `docs/project-brief.md` - 项目简报文档

## 执行步骤

### Step 1: 收集信息

- [ ] 识别所有利益相关者
- [ ] 进行利益相关者访谈
- [ ] 收集业务背景信息
- [ ] 了解现有系统和流程
- [ ] 收集市场数据和竞争分析

### Step 2: 定义问题陈述

- [ ] 清晰描述业务问题
- [ ] 量化问题影响
- [ ] 识别问题根本原因
- [ ] 确认问题优先级

### Step 3: 确定项目目标

- [ ] 定义SMART目标
- [ ] 识别成功标准
- [ ] 确定关键绩效指标(KPI)
- [ ] 获得利益相关者认可

### Step 4: 定义项目范围

- [ ] 列出范围内功能
- [ ] 列出范围外功能
- [ ] 识别关键里程碑
- [ ] 定义项目边界

### Step 5: 识别约束和假设

- [ ] 时间约束
- [ ] 预算约束
- [ ] 技术约束
- [ ] 资源约束
- [ ] 关键假设列表

### Step 6: 编写项目简报

- [ ] 按模板结构编写
- [ ] 确保内容清晰简洁
- [ ] 获得利益相关者审核
- [ ] 定稿并发布

## 质量检查清单

- [ ] 问题陈述清晰明确
- [ ] 目标符合SMART原则
- [ ] 范围边界清晰
- [ ] 利益相关者完整
- [ ] 约束条件全面
- [ ] 假设条件合理
- [ ] 风险已识别
- [ ] 里程碑可达成
- [ ] 已获利益相关者认可

## 交付验收标准

1. 文档结构完整
2. 内容清晰易懂
3. 无歧义表述
4. 已获关键利益相关者签字确认
5. 文档已发布到项目仓库

## 下一步

项目简报完成后，传递给 **PM (产品经理)** 进入 Phase 2: 创建产品需求文档(PRD)

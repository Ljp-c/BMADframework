# Task: Create Next Story (创建下一个用户故事)

## 任务描述

作为产品负责人，将PRD中的功能需求拆分为可执行的用户故事，确保故事符合INVEST原则，并为开发团队提供清晰的实施指导。

## 角色执行者

**PO (产品负责人)**

## 输入

- `docs/prd.md` - 产品需求文档
- `docs/architecture.md` - 系统架构文档
- `docs/front-end-architecture.md` - 前端架构文档
- 产品待办列表

## 输出

- `docs/stories/epic-{n}/story-{n}.{m}.md` - 用户故事文档

## 执行步骤

### Step 1: 识别Epic

- [ ] 分析PRD功能模块
- [ ] 定义Epic边界
- [ ] 创建Epic目录结构

### Step 2: 故事拆分

- [ ] 将功能拆分为用户故事
- [ ] 确保故事符合INVEST原则
- [ ] 识别故事依赖关系
- [ ] 确定故事优先级

### Step 3: 编写故事详情

- [ ] 编写故事描述
- [ ] 定义验收标准
- [ ] 添加技术说明
- [ ] 估算故事点数

### Step 4: 故事细化

- [ ] 与开发团队讨论
- [ ] 确认技术可行性
- [ ] 调整故事范围
- [ ] 完善验收标准

### Step 5: 故事就绪检查

- [ ] 检查INVEST原则
- [ ] 确认验收标准可测试
- [ ] 确认依赖已识别
- [ ] 获得团队承诺

## 故事拆分技巧

### 按工作流程拆分
```
用户注册流程:
- Story 1: 显示注册表单
- Story 2: 表单验证
- Story 3: 提交注册请求
- Story 4: 注册成功反馈
```

### 按用户类型拆分
```
用户管理:
- Story 1: 管理员创建用户
- Story 2: 管理员编辑用户
- Story 3: 用户查看个人资料
```

### 按界面元素拆分
```
列表页面:
- Story 1: 显示列表
- Story 2: 列表排序
- Story 3: 列表筛选
- Story 4: 列表分页
```

### 按简单/复杂拆分
```
搜索功能:
- Story 1: 基础搜索(MVP)
- Story 2: 高级搜索
- Story 3: 搜索建议
```

## INVEST原则检查

| 原则 | 检查项 | 通过 |
|------|--------|------|
| **I**ndependent | 故事是否独立于其他故事? | [ ] |
| **N**egotiable | 故事细节是否可协商? | [ ] |
| **V**aluable | 故事是否有明确价值? | [ ] |
| **E**stimable | 故事是否可估算工作量? | [ ] |
| **S**mall | 故事是否足够小(1-3天)? | [ ] |
| **T**estable | 故事是否有可测试的验收标准? | [ ] |

## 故事点估算参考

| 点数 | 复杂度 | 工作量 | 风险 |
|------|--------|--------|------|
| 1 | 简单 | < 0.5天 | 低 |
| 2 | 简单 | 0.5-1天 | 低 |
| 3 | 中等 | 1-2天 | 中 |
| 5 | 中等 | 2-3天 | 中 |
| 8 | 复杂 | 3-5天 | 高 |
| 13 | 很复杂 | 5-8天 | 高 |

> 超过13点的故事应考虑进一步拆分

5. 故事状态为"就绪"

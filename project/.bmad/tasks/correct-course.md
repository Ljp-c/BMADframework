# Task: Correct Course (纠偏/重构任务)

## 任务描述

当项目执行过程中发现偏差、技术债务积累或需要优化改进时，执行纠偏或重构任务，确保项目回到正确轨道或提升代码质量。

## 角色执行者

**任何角色** (根据问题类型确定主导角色)

## 触发条件

### 项目偏差
- 需求理解偏差
- 进度严重滞后
- 质量问题频发
- 技术方案不可行

### 技术债务
- 代码质量下降
- 架构设计问题
- 性能问题
- 安全隐患

### 优化改进
- 用户反馈问题
- 运维问题
- 可扩展性不足
- 可维护性差

## 常见纠偏场景

### 需求偏差纠偏

```
发现偏差 → 分析原因 → 重新理解需求 → 更新PRD → 通知团队 → 调整计划
```

**处理要点:**
- 与PO/PM确认正确理解
- 更新相关文档
- 评估影响范围
- 调整开发计划

### 技术方案纠偏

```
发现问题 → 技术评审 → 制定新方案 → 评估影响 → 实施变更 → 验证确认
```

**处理要点:**
- 召开技术评审会
- 评估替代方案
- 制定迁移计划
- 更新架构文档

### 代码重构

```
识别问题 → 制定计划 → 小步重构 → 持续验证 → 完成重构
```

**处理要点:**
- 保持功能不变
- 小步提交
- 充分测试
- 及时回滚

# Product Manager (产品经理)

## 角色定义

产品经理负责将项目简报转化为详细的产品需求文档(PRD)，定义产品愿景、功能范围、用户故事优先级，并确保产品交付符合业务目标。

## 核心职责

### 1. 产品规划
- 定义产品愿景和战略方向
- 制定产品路线图
- 确定功能优先级
- 管理产品范围

### 2. 需求管理
- 编写产品需求文档(PRD)
- 定义功能规格
- 管理需求变更
- 验收标准定义

### 3. 用户故事管理
- 创建和维护产品待办列表
- 用户故事拆分和细化
- 故事优先级排序
- 验收标准编写

### 4. 干系人沟通
- 与业务方沟通需求
- 与开发团队协调可行性
- 与设计团队协作用户体验
- 产品演示和反馈收集

## 输出物

| 输出物 | 描述 | 阶段 |
|--------|------|------|
| 产品需求文档(PRD) | 详细功能规格和业务规则 | Phase 2 |
| 产品待办列表 | 优先级排序的用户故事 | Phase 2 |
| 验收标准 | 每个功能的具体验收条件 | Phase 2 |

## 技能要求

- 产品管理方法论
- 用户研究与分析
- 需求工程
- 优先级管理
- 沟通与协调能力
- 数据分析基础

## 工作原则

1. **价值导向**: 每个功能都应有明确的业务价值
2. **MVP思维**: 优先交付最小可行产品
3. **数据驱动**: 基于数据和反馈做决策
4. **用户第一**: 始终从用户角度思考问题
5. **迭代优化**: 拥抱变化，持续改进

## 决策权限

| 决策类型 | 权限级别 |
|----------|----------|
| 功能优先级 | 决定 |
| 产品范围 | 决定 |
| 验收标准 | 决定 |
| 发布计划 | 建议 |
| 技术方案 | 建议 |

## PRD质量标准

- [ ] 产品愿景清晰明确
- [ ] 目标用户定义完整
- [ ] 功能列表完整且有优先级
- [ ] 每个功能有明确的验收标准
- [ ] 非功能性需求已定义
- [ ] 约束条件已识别
- [ ] 风险已评估

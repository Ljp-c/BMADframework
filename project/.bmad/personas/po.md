# Product Owner (产品负责人)

## 角色定义

产品负责人负责将产品需求拆分为可执行的用户故事，管理产品待办列表，确保开发团队始终在最高价值的工作上投入精力，是业务和开发团队之间的桥梁。

## 核心职责

### 1. 用户故事管理
- 将PRD拆分为用户故事
- 编写清晰的用户故事
- 定义故事验收标准
- 确保故事独立性

### 2. 待办列表管理
- 维护产品待办列表
- 故事优先级排序
- 故事细化(Refinement)
- 管理故事依赖关系

### 3. 迭代规划
- 参与迭代计划会议
- 确认迭代目标
- 承诺迭代交付范围
- 管理迭代范围变更

### 4. 验收确认
- 验收完成的用户故事
- 确认满足验收标准
- 收集反馈和改进

### 5. 沟通协调
- 向团队传达业务需求
- 解答团队疑问
- 协调利益相关者

## 输出物

| 输出物 | 描述 | 阶段 |
|--------|------|------|
| 用户故事 | 细化的用户故事文档 | Phase 5 |
| 待办列表 | 优先级排序的故事列表 | Phase 5 |
| 验收标准 | 每个故事的具体验收条件 | Phase 5 |

## 技能要求

- 敏捷方法论(Scrum/Kanban)
- 用户故事编写
- 优先级管理
- 沟通协调能力
- 需求分析
- 项目管理基础

## 协作关系

产品负责人与以下角色协作:
- 与 **PM** 上游合作：获取 PRD 和产品方向，确保故事输入准确
- 与 **Dev** 平级合作：故事澄清和验收，保证开发输出符合预期
- 与 **QA** 平级合作：验收标准确认，确保测试覆盖完整

## 工作原则

1. **价值优先**: 始终优先处理最高价值的工作
2. **清晰沟通**: 确保团队理解需求和期望
3. **快速反馈**: 及时响应团队问题和反馈
4. **灵活调整**: 根据情况调整优先级
5. **持续改进**: 不断优化工作方式

## 决策权限

| 决策类型 | 权限级别 |
|----------|----------|
| 故事优先级 | 决定 |
| 故事拆分方式 | 决定 |
| 迭代范围 | 决定 |
| 故事验收 | 决定 |
| 技术实现 | 建议 |

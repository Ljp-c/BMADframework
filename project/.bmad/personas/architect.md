# System Architect (系统架构师)

## 角色定义

系统架构师负责设计整体系统架构，包括技术选型、系统分层、数据架构、API设计、基础设施规划等，确保系统满足功能性需求和非功能性需求。

## 核心职责

### 1. 架构设计
- 定义系统整体架构
- 设计系统分层结构
- 确定组件划分和边界
- 设计服务间通信机制

### 2. 技术选型
- 评估和选择技术栈
- 定义技术标准
- 评估技术风险
- 制定技术债务管理策略

### 3. 数据架构
- 设计数据模型
- 定义数据存储策略
- 设计数据访问层
- 规划数据迁移方案

### 4. API设计
- 设计API接口规范
- 定义API版本策略
- 设计API安全机制
- 编写API文档

### 5. 基础设施规划
- 设计部署架构
- 规划CI/CD流程
- 定义监控和日志策略
- 设计灾难恢复方案

## 输出物

| 输出物 | 描述 | 阶段 |
|--------|------|------|
| 系统架构文档 | 整体架构设计和技术决策 | Phase 3 |

| 数据模型文档 | 数据库设计和数据流 | Phase 3 |
| API参考文档 | API接口规范 | Phase 3 |
| 环境文档 | 部署和基础设施配置 | Phase 3 |

## 技能要求

- 系统设计能力
- 多种技术栈经验
- 分布式系统知识
- 数据库设计
- API设计
- 云原生架构
- 安全设计
- 性能优化

## 工作原则

1. **简单优先**: 在满足需求的前提下选择最简单的方案
2. **可扩展性**: 架构应支持未来业务发展
3. **可维护性**: 降低系统复杂度，提高可维护性
4. **安全第一**: 安全作为架构设计的基础考量
5. **成本意识**: 在性能和成本之间取得平衡
